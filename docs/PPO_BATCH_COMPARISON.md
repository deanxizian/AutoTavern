# PPO 采样、批次与预算对照

核对日期：2026-10-31，Asia/Shanghai。外部数值来自官方文档／代码和论文；本地数值来自实验配置。

## “420 万样本／轮”到底是什么

本文统一用 **PPO 迭代（iteration）** 表示“先采一批 rollout，再训练这批数据”的循环，
不再用单独的“轮”指代它，以免与 epoch 或 Adam step 混淆。

论文早期实验写的是每次 PPO 迭代约 420 万次决策；本地旧全量方案具体采用：

```text
256 个并行环境 × 每环境采样 16,384 步
= 4,194,304 个新 sample / PPO iteration
= 512 个 minibatch × 8,192 sample
= 4,096 个 microbatch × 1,024 sample（epoch=1 时）
```

一个 sample 是受控玩家的一次动作转移，包含观测、动作、奖励、旧概率、值等训练信息，
不是一局游戏；七个脚本对手的内部动作不计入受控玩家的 sample 数。
环境可以在采样期间结束并重开多局，所以 sample 数也不能直接换算为固定的对局数。

- **epoch**：把本次 rollout 遍历一次；epoch=2 是对同一批样本遍历两次。
- **minibatch**：一次有效 Adam 更新消费的样本，本地为 8,192。
- **microbatch**：将有效 minibatch 切分为较小前后向计算；本地为 1,024，累积 8 次后更新一次 Adam。
- **TensorBoard Step**：本地日志使用累计新采样决策数，不是 Adam 次数或 PPO 迭代数。

计算公式（完整整除且未提前停止时）：

```text
新样本 B / PPO iteration = 并行环境数 N × 每环境采样步数 T
minibatch 数 / epoch     = B / 有效 minibatch 大小 b
Adam 次数 / PPO iteration = (B / b) × epochs E
总新样本                 = B × PPO iterations I
总 Adam 次数             = (B / b) × E × I
```

例如旧方案 epoch=1 时，一次 PPO 迭代含 512 次 Adam 更新；epoch=2 时为 1,024 次 Adam 更新，
新采样量仍是 4,194,304，训练时样本呈现次数变成 8,388,608。梯度累积不会把 Adam 次数乘以 8。

CleanRL 的循环对指定总步数做向下整除：PPO 请求 500,000，实际 976 × 512 = 499,712；
TrXL 请求 200,000,000，实际 12,207 × 16,384 = 199,999,488。

这些总次数是按官方默认配置和循环计算的，不是本机训练实测。
SB3 本身没有固定训练总量，由调用 learn() 时指定。

## 候选配置与总预算

候选采用 256 环境 × 512 步 = 131,072 个新样本，minibatch=8,192，epoch=2：
每次 PPO 迭代有 16 个 minibatch／epoch、最多 32 次 Adam 更新。
这只是讨论中的起点，尚未写入正式配置或运行；它不是已经验证更优的参数。

保留 300 次 PPO 迭代时：

```text
旧方案：4,194,304 × 300 = 1,258,291,200 个新样本；最多 153,600 次 Adam 更新。
候选：    131,072 × 300 =    39,321,600 个新样本；最多   9,600 次 Adam 更新。
试跑：      8,192 × 100 =       819,200 个新样本；实际     100 次 Adam 更新。
```

候选在相同 300 次迭代下，新样本量只有旧方案的 1/32，Adam 上限为 1/16，不能按相同训练预算比较。
若保持旧方案的约 12.58 亿新样本不变，候选需要 **9,600 次 PPO 迭代**；因为 epoch=2，
其 Adam 更新上限为 307,200，总训练呈现样本数也会翻倍，需要重新估算训练耗时。

旧 52–54 小时（BF16 外推 39–42 小时）对应旧 rollout／epoch 方案；本次试跑实测约 221 秒。
候选尚无完整耗时测量，不能沿用其中任意一个时间。
旧方案的无损 rollout 缓存约 13.07 GiB；相同编码下候选约 0.408 GiB，不含进程和解包等额外内存。

## 如何看待已经完成的试跑

试跑的 rollout 恰好等于一个 minibatch，且 epoch=1；梯度计算前没有其他 Adam 更新，
旧策略与当前策略基本相同，所以 ratio 约为 1，clip fraction／更新前 KL 接近零。
这时裁剪目标没有机会约束同批数据上的后续优化步骤；本次结果适合验证采样、梯度、保存、评估和 TensorBoard 管线，
不应把零 KL 当作步后稳定的证据，也不应将其视为标准多 minibatch PPO 学习效果的充分验证。

首版仍完成了用户要求的 100 个 minibatch，使用 819,200 个新样本；
它的总样本量为旧全量方案的 1/1,536。评估后仅保留第 25 次更新的最佳模型，完整指标仍保存。
结果见 [首版实验](../experiments/20261031-ppo-small-v1-100-minibatches/README.md)。
