# 学习者与固定 bot 的独立 Actor 采样试验

2026-10-31，北京时间。独立性能原型，不启动第二次训练、不更新权重、不生成检查点。

两次短测汇总，采样吞吐从 **1,181 提高到 6,504 个学习者样本／秒，约 5.51 倍**，采样耗时减少 **81.8%**。
这个比例仅表示采样环节，不表示完整 PPO 训练也快 5.51 倍。

## 相同设置

- RTX 5080，256 局并发，4 个模拟器线程，Torch CPU 线程数 2。
- 每局 6 个原生脚本、1 个固定 V1、1 个学习者。学习者和固定 V1 使用两个独立策略实例，分别合批。
- 两个角色都加载第一次实验的 V1，用 BF16 网络前向，参数、value、log-prob 和概率保持 FP32。
- 每组每局恰好采集 128 个学习者决策，共 32,768 个。两个种子 43／44，每种调度合计 65,536 个样本。
- 相同 60 动作回合上限；操作成本 0.0001，循环成本 0.0002。没有推理动作过滤。
- 预热后按同步／新调度／新调度／同步的 ABBA 顺序测量，包含模拟器、观测提取、推理、CPU 传输、奖励与标量审计；不包含初始化和权重加载。

## 为什么更快

原驱动要求每次 VecEnv.step 都让全部学习者抵达下一个决策点。已经就绪的游戏整局暂停，
只为少数慢局反复调用固定 V1，产生了大量 batch=1／2 的前向。

原型在每个原生推进时刻收集所有就绪角色，按 `learner` 和 `bot_v1` 两个策略身份分别前向。
某局学习者就绪后可以立即继续，其余局仍可推进自己的固定 bot。不同权重的角色始终分批推理；
两者初始权重相同也不合并，以便以后学习者更新而 V1 固定。

每个学习者动作记录当时的公开观测、action、value 和 log-prob，等该局学习者再次就绪或终局时才完成 transition。
终局奖励只结算一次；只有学习者 transition 进入采样输出。各局到达自己的 rollout 配额后才暂停，
计时包含最后慢局的等待。不是跨 PPO 更新使用旧权重采样，也没有实现 CPU／GPU 流水重叠。

学习者 batch 略小、推理次数变多，但固定 V1 不再频繁使用极小 batch，总体收益明显。

## 正确性与边界

测试使用不同确定性规则控制两个角色，逐局对比新旧驱动共 540 个 transition，
核对前后完整观测、动作、奖励、终局、名次、episode 次序和最终原生存档。
测试覆盖两段连续 rollout、1／3 线程及至少 6 次终局，两个线程设置均通过。
真实 GPU 短测额外检查精确样本配额、合法动作、样本归属、FP32 有限标量、两个角色的原始 BF16 head 输出。

GPU 性能短测的每组仅 128 个学习者决策／局，尚未有完整对局终局；终局逻辑由上述确定性测试覆盖。
不同调度会改变随机数消耗顺序，BF16 在不同 batch 下也可能有微小数值差异，
因此相同种子并不表示相同对局轨迹；固定 bot 的总动作数略有不同。这里不是胜率评测或训练收敛结论。

实现位于 [actor_sampling.py](../../../python/taverngym/learning/actor_sampling.py)，尚未接入正式 PPO 的缓存、GAE 和训练入口。
现有训练驱动保持原行为。上一次第二轮试跑的非法动作失败没有在本次原型中专门定位或宣称修复。

V1 来源 SHA256：`7173d82343fcc79742838c72725c582966a3c5b7c84e15014debea292f32de24`。
停止的第二轮 `latest_model.zip` SHA256：`a91db3db987c989fa439d540ffb9676ae4ce5eb51fafc10c7e0b750544551dac`。

## 复现

```bash
uv run --locked --group train --extra test python \
  experiments/20261031-infra/20261031-unified-actor-sampling/run.py
uv run --locked --group train --extra test python -m pytest -q tests/test_actor_sampling.py
```

脚本读取本地 V1 权重，需要 CUDA／BF16；不上传模型或启动线上记录。
