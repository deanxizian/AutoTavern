# 批量动作因跨席位事件失效的修复

2026-10-31，北京时间。第二轮在第 23 次 PPO 采样时退出；前 22 次 PPO、704 次 Adam 已完整保存。
原始失败现场保存在正式实验的 `attempts/20261031-172045-stale-action/`。

## 根因

同一批中的多个受控席位根据同一份快照选择动作，随后模拟器按席位依次执行。
失败时，角色 0／席位 1 在招募阶段死亡，触发角色 2／席位 6 的“大猫”英雄技能发现。
角色 2 此前选出的 `Move { from: 4, to: 1 }`（动作 225）在最初快照中合法，
执行时却必须先处理新出现的发现，因此旧驱动将它记为非法动作并中止训练。

这不是策略绕过合法掩码。存档确认席位 1 已死亡、名次为 8，席位 6 新增
`TB_BaconShop_HP_080` 的发现菜单，原始移动已不合法。

## 行为变化

每个原生批次保存各角色所选动作的初始合法性及当前菜单摘要。
执行时，如果较早席位使较晚角色的动作失效、角色不再需要动作，或菜单发生替换，
返回 `deferred=True`，不执行该动作、不收取非法动作惩罚；调用者重新观察后再决策。
菜单比较包含深度和顶部内容，因此也覆盖动作编号仍合法、但它们已对应另一份发现的问题。

起初就非法的动作、或始终合法却被规则执行器拒绝的动作，仍返回 `rejected=True` 并严格报错。
没有自动代替操作、没有伪造 EndTurn，也没有丢掉真实学习者动作。
学习者始终是首个角色；若它出现延后则显式报错。固定对手的延后推理不会进入 PPO 缓存，
也不计为实际执行的对手决策。

公共 Python `BatchEnv.step` 的返回结构不变，metadata 增加 `deferred` 布尔数组。
`system/actor_deferred_opponent_actions` 按 PPO 记录此类延后数量。
