# 模型对手数量与 BF16 推理短测

2026-10-31 用户询问：只用 1 个 V1 模型对手是否更快，推理是否已经并行，以及是否能用 BF16。
[run.py](run.py) 使用同一份固定 V1 权重测试，不更新优化器或保存探针模型；
正式实验 02 保持原来的 4 模型 + 3 脚本、FP32/TF32 配置，未暂停或重启。

**测试与正式训练共享 GPU/CPU，绝对速度不是独占设备的峰值。**
对手数量采用 1、4、4、1 的交错顺序，每块 256 环境 × 32 学习者步，
每种配置合计 16,384 个样本；各配置保留独立 CUDA 采样随机流。
学习者与对手均使用固定 V1，仅测启动阶段的采样吞吐，不能据此推断训练后的实力。

| 固定模型对手 + 脚本 | 采样耗时 | 学习者样本／秒 | 对手推理调用 | 对手平均／中位 batch |
| --- | ---: | ---: | ---: | ---: |
| 1 + 6 | 26.75 秒 | 612.4 | 2,408 | 7.93 / 2 |
| 4 + 3 | 42.54 秒 | 385.2 | 2,664 | 26.63 / 6.5 |

此短测中改成 1 个模型对手快约 1.59 倍。对手决策量下降，但同步等待使推理调用数并未按四分之一下降。
这项结果支持优先优化调度和批量利用，不能直接按对手数量线性估算完整训练时长。

另在已采集的相同公开观测上，交替测试 GPU 常驻输入的神经网络 forward 与 FP32 masked softmax，
每种精度每个 batch 重复 8 次，表中为墙钟中位数，均包含 GPU 同步。

| batch | FP32、允许 TF32 | BF16 autocast | FP32 耗时 / BF16 耗时 |
| --- | ---: | ---: | ---: |
| 32 | 2.36 ms | 4.01 ms | 0.59× |
| 256 | 6.35 ms | 5.97 ms | 1.06× |
| 1,024 | 25.51 ms | 19.97 ms | 1.28× |

BF16 可以直接使用现有 FP32 权重；原始 head logits 为 BF16，概率计算转回 FP32。
不需要先将全部权重、观测或归一化算子强制转换成 BF16，也不改变保存文件。
本次 BF16 与 FP32 在 batch 256/1,024 观测上的贪心动作分歧约为 1.9%，不是胜率验证。
正式切换仍需复核整局名次和循环；学习者采样精度与 PPO 更新前向也应一致。

原始计时、概率差异、推理调用计数和正式任务结束窗口状态见 [results.json](results.json)。
报告中的 BF16 logits dtype 标签另用独立 forward 复核；数值与计时测量本身未改动。
