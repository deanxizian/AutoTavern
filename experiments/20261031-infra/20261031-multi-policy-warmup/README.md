# 通用对手角色池、Adam 续接与 warmup

原生八人模拟器保持不变，Python 调度支持多个命名固定策略组，每组填写模型与席位数。
同一组共享一份模型，跨局就绪请求按策略合批；只有学习者转移写入 PPO 缓存。
学习者采样和固定策略前向均无梯度，PPO 重算时只训练学习者。

`--continue-stage` 保留 Adam moments 和原始 step，使用持久化 offset 将阶段日志从零计数。
旧 `--warm-start` 的清空 Adam 行为不变，旧检查点没有 offset 时默认为零。
新增 `warmup_linear` 调度，按阶段采样进度进行 warmup 和线性衰减，同一预算断点恢复不重启 warmup。

116 项 Python 测试通过，含 CUDA 和离线 W&B。
新增覆盖了两种／三种固定策略的同步与独立调度轨迹一致、固定权重不变及梯度隔离，
Adam moments 的精确保留、阶段日志从零开始、检查点往返，以及实际 CLI 的 LR 变化。
实际规模预检入口：`preflight.py`，结果保存为 `full-ppo-preflight.json`；预检更新丢弃、不保存新模型。

实际预检通过：128 环境 × 1,024 步，2 固定 V1 + 3 固定 V2 + 2 脚本，学习者随机 BF16。
共 131,072 个学习者样本、119 个完成的学习者 episode、16 次新 Adam；
采样 36.95 秒，更新 8.12 秒，总计 45.12 秒，GPU 峰值 allocated 3.81 GiB。
Adam 从 3,200 续接到 3,216，阶段更新计数为 16；当时 100 PPO 预案下首轮 LR 为 4.4e-6。
采样没有保留梯度图，两种固定策略的参数、梯度与源 ZIP 均保持不变。
随后按用户要求保持总训练预算，将正式目标改为 200 PPO，首轮 LR 为 3.7e-6，
warmup 仍占总进度 5%（10 PPO／160 Adam）；环境数、每次 PPO 的工作量与冻结隔离机制不变。
