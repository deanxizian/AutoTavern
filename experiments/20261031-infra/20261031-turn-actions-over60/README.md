# 单回合第 60 步之后的行为

冻结当前 V3 检查点，随机采样与贪心推理各 64 个完整学习者 episode。
对手为 2 个固定 V1 + 3 个固定 V2 + 2 个脚本；所有模型均 BF16 前向。
这不是训练，不修改正在进行的实验或其参数。

全局原生 `turn_action_caps=[60]` 保持不变，仅对学习者设置原生 `uncapped` 标志。
因此对手仍受 60 阈值约束；学习者则在达到诊断阈值 200、且没有待处理选择时，只允许 EndTurn。
这是有限的诊断窗口，不是无限制运行。EndTurn 本身也计数，所以触顶回合通常记录 201 步。
各局独立推进，按策略身份合批推理，仅记录每条 lane 的第一个学习者 episode。

- `actions`：该游戏回合的学习者操作总数，包括 EndTurn 与待处理选择。
- `after60`：第 61 步及之后的操作数，包括 EndTurn。
- `non_end_after60`：额外操作数，排除 EndTurn；用户关心的“还会继续操作多少步”使用此口径。
- `cycles_after60`：这些额外操作中，被已有无进展状态重复检测器识别的返回次数。
- `forced_end_at200`：诊断保护阈值强制结束的次数；这些回合的无限制长度仍然未知。

`config.json` 保存检查点 PPO 迭代与 SHA-256；每模式的 `*-turns.jsonl` 保存逐回合计数，
`*-episodes.json` 保存学习者结果，汇总为 `results.json`。
包含学习者最终淘汰／获胜所在的回合；只统计其实际经历的回合，不是完整八人局后续所有回合。
本测试只观察额外操作的数量与类型，不能据此证明额外操作有收益。

首次同步驱动诊断因跨局等待过慢而停止，未完成 episode；其控制台保存在本地
`console-synchronous-attempt.txt`。正式统计使用独立推进驱动，失败尝试不计入结果。

## 测量结果

2026-10-31，冻结 V3 的 PPO 144 快照；2 固定 V1 + 3 固定 V2 + 2 脚本，BF16，
随机与贪心各 64 个学习者 episode。正式统计耗时约 240 秒，所有对手仍保持 60 阈值。

| 指标 | 随机采样 | 贪心推理 |
| --- | ---: | ---: |
| 统计的学习者游戏回合数 | 945 | 978 |
| 第 60 步后仍执行非 End 操作的回合 | 718（75.98%） | 888（90.80%） |
| 上述回合平均额外非 End 操作 | 116.42 | 140.06 |
| 上述额外操作的 P50／P90／P95 | 140／140／140 | 140／140／140 |
| 触及 200 保护阈值的回合 | 489（全部回合的 51.75%） | 888（全部回合的 90.80%） |
| 超过 60 后继续操作、最终又触及 200 的比例 | 68.11% | 100% |
| 额外非 End 操作中，移动／冻结占比 | 92.34% | 93.43% |
| 额外非 End 操作中，被识别为无进展重复的占比 | 19.64% | 93.41% |

贪心模式下，本次所有超过 60 后仍继续操作的回合都依赖 200 阈值收尾。
这表明该策略对外部操作上限有明显依赖；不能将额外步骤都视为正常的有收益操作需求。
触及 200 的回合仍存在右侧截断，真实无限制长度未知；待处理选择可继续解决，
加上最后的 EndTurn，观察到的最长回合记录为 203 步。
比例以本次所经历的回合为分母，包括淘汰回合；同局回合相关，未将它们视为独立对局做显著性检验。
