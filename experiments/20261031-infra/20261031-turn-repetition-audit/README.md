# 超过 60 步的重复行为复核

2026-10-31，冻结 V3 PPO150；2 个固定 V1 + 3 个固定 V2 + 2 个脚本，
学习者随机／贪心各 16 个完整 episode，所有模型 BF16 前向。
仅学习者放宽至诊断阈值 200，对手仍为 60；未训练、未修改正式奖励或运行参数。
与此前 PPO144 的各 64 局探针分开保存，不能合并为同一固定模型的测量。

## 方法

原奖励检测器仅在连续 Move／Freeze 段内检查相同可见状态，其他动作会清空历史。
本次追加**跨所有动作类型、同一游戏回合内**的可见状态返回检测：
对原生观测的完整 features 和 cards 做哈希，忽略合法动作掩码，
统计第 61 步及之后的非 End 动作是否回到本回合先前见过的状态。
这不是比较动作 ID：同一动作可以有正常用途，必须同时检查状态。

## 结果

| 指标 | 随机采样 | 贪心推理 |
| --- | ---: | ---: |
| 学习者游戏回合数 | 249 | 244 |
| 第 60 步后继续执行非 End 的回合 | 192 | 224 |
| 上述回合中，原 Move／Freeze 检测器发现重复 | 176 | 203 |
| 上述回合中，全动作检测发现可见重复 | 188（97.92%） | 224（100%） |
| 第 60 步后未发现可见重复的回合 | 4 | 0 |
| 第 60 步后的非 End 动作 | 22,826 | 31,380 |
| 其中返回已见可见状态的动作 | 6,176（27.06%） | 31,378（99.99%） |
| 最终触及 200 诊断阈值的回合 | 128 | 224 |

逐动作记录发现 `Play(46) → Cancel(7) → Play(46) → Cancel(7)` 循环，
也有英雄技能相关可见状态重复。它们不在现有 Move／Freeze 重复惩罚的覆盖范围内。
贪心模式的所有额外动作类型为 Move、Play、Cancel、Choose、HeroPower0，
本次未观察到第 60 步之后消耗金币的动作。

随机模式的额外动作还包含买牌 28 次、卖牌 60 次、刷新 86 次、升级 2 次。
例如某回合第 74 步购买，金币从 1 变为 0；这些不是单纯的位置交换。
四个未检测到额外重复的回合中，仍有大量移动：例如一个回合额外 61 步，
包含 52 次移动、2 次冻结、5 次刷新、1 次出牌与1次卖牌。

## 判断与限制

- 贪心模式明显陷入循环；扩大上限主要会延长循环，没有证据说明它需要这么多有效操作。
- 随机模式不是所有额外动作都重复。不能把“97.92% 回合含重复”写成“97.92% 动作重复”。
- 未返回同一状态不代表有收益：反复生成不同排列也可能浪费操作。
- 可见状态相同不严格保证隐藏计数器、随机数状态等完全相同；本检测是行为诊断，不是规则等价证明。
- 60 的硬上限可能截掉模型晚做的购买等操作；这不证明合理策略本身需要超过 60 步，前面也可能浪费了预算。
- 200 是右侧截断。测试未比较同一第 60 步状态下立即 End 与继续操作的后续收益，不能据此证明 60 普遍足够或不够。
- 优先补齐重复检测／惩罚，再用同状态配对评估比较 60／更高预算；不能仅因本测量就直接加大上限或惩罚全部触顶回合。

## 记录与复核

- `config.json`：固定 PPO150 路径、SHA-256、对手、精度、种子与检测口径。
- `results.json`、`*-turns.jsonl`、`*-episodes.json`：汇总及逐回合、逐局原始记录。
- `examples.json`：两步可见循环及额外金币消耗的具体动作，含状态哈希。
- `previous-probe-breakdown.json`：从此前 PPO144 记录计算的独立统计，不与本次合并。
- `*-actions.jsonl`：本地保留完整动作轨迹，忽略 Git；含 step、action、前后状态哈希、金币变化。
- `verification.json`：逐动作回算计数与逐回合统计一致。

复核：`.venv/bin/python experiments/20261031-infra/20261031-turn-repetition-audit/analyze.py`。
`run.py` 为只读诊断入口；已有结果时拒绝覆盖，正式训练代码未改变。
