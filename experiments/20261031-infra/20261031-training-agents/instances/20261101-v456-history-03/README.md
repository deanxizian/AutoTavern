# 历史对手链路 03：每次重复扣 0.01，60 步强制 End

北京时间 2026-11-01，用户最终确认：每次返回本回合已见的完整模型可见状态固定扣 `0.01`，
不是单次递增罚额；10 次累计 0.1，30 次累计 0.3。操作成本为 0，使用 all_actions 检测。
`cycle_forfeit_repetitions=null`、`turn_action_forfeit_limit=null`，两种提前判负都关闭。
原生 `turn_action_caps=[60]` 保持：到限后只允许 End（待选菜单先按原生规则处理），
正常结束招募、进入战斗并继续对局，不因循环或动作预算人工淘汰。

每阶段 128 环境 × 1024 步，minibatch8192、microbatch1024、epoch1，LR 固定 `1e-5`。
继承所选 best 的完整网络和 Adam moments／历史时钟，重置阶段计数。V4 的两个冻结 V3
对手独立加载原 V3 权重；后续冻结 V4+ 必须绑定本实例实际阶段 best，按自身新协议。
V1/V2/V3 保持历史规则，不追溯新增惩罚或提前判负。

每阶段自己的固定阵容、BF16、固定对手随机采样，学习者随机／贪心各 64 局，PPO0/50/100。
只有随机平均名次严格降低才替换 best，PPO0 参与、同分留早；不同阵容 val 不横比。
initial/best/final 独立每模式各 128 局，只报告，不选模、不排弱、不决定扩展。

W&B 每阶段独立 run，train 横轴为实际阶段 Adam，val 起点为 0。以下均基于已完成整局，
先计算每局值再对完成局取均值，训练和 val/greedy 使用同一定义：

| 指标 | 定义 |
| --- | --- |
| `cycle_returns` | 每局返回已见完整可见状态的事件次数 |
| `cycle_return_fraction` | 每局 `cycle_returns / actions_per_game`，再按局均值，非两个均值相除 |
| `max_consecutive_cycle_returns` | 每局最长连续状态返回次数，再按局均值；新状态/End/turn/reset/restore 清零 |
| `cycle_penalty` | 每局累计循环扣分，等于 `-0.01 * cycle_returns` |
| `cap_end_rate` | 每局达到原生动作上限后强制 End 的招募回合比例 |

`actions_per_game` 包括全部学习者策略决策（含英雄选择和实际 End）。重复动作产生新可见状态不罚。
新连续返回指标不同于旧 `max_consecutive_cycles`（完整闭环判负计数）；后者不用于本轮诊断。
完整开发验证保存每局真实名次、终局回合、决策数与奖励组成，不把单次动作当独立整局样本。

V6 后的 gate 只检查三阶段训练/独立评估/留存完成，以及没有未解决的运行、数值、动作拒绝、
真实终局或评估异常。两种 forfeit 率应为零，仅作为协议完整性检查，不是训练改善证据。
若 V4/V5/V6 三阶段 best 全部仍为各自 PPO0，视为连续三阶段未改善，停在 V6，不开放条件预算。
不擅自设置重复比例、Greedy 或独立 test 的晋级门槛。无问题才使用额外 300 PPO，否则停在 V6。

最新用户长期规则覆盖此前配比：**从 V5 起，全部可用历史 bot 中开发排名最强三版各 2 席，
加 1 个脚本**。不保护最新必入，不要求每版保留一席；未入当期池的权重不删，未来可再次入选。
可用历史包括静态 V1/V2/V3 和本实例每个已完成阶段的实际 best，不包括旧 01/02 的 V4 更新。
学习者始终继承前阶段 best／Adam，不改成排名第一的对手。

每阶段选池一次：固定参考 2 V1 + 2 V2 + 2 V3 + 1 脚本，随机 BF16，每候选 64 局，开发种子
`60000007`，按候选自身协议。随机平均名次从低到高取前三，同分优先较新；此 tie 只用于选池，
不改变阶段 best 相等留早的规则。V5/V6 各 4/5 候选；条件 V7/V8/V9 各 6/7/8 候选。
