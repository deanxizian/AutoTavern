# 实验 01：换位与冻结循环诊断

日期：2026-10-31，Asia/Shanghai。状态：**完成**。
按用户要求，只检查已有模型在模拟器中的动作，不修改策略、不训练，不涉及外部实战项目。

## 结论

原生观测和合法动作掩码下，确实存在换位回退与冻结／解冻往返。
使用同一份第 100 轮模型，分别执行确定性 argmax 与按策略概率采样，各 64 局：

| 项目 | 确定性 argmax | 概率采样 |
| --- | ---: | ---: |
| 完整对局 | 64 | 64 |
| 发生换位回退的对局 | **64/64** | **64/64** |
| 发生冻结往返的对局 | **63/64** | **64/64** |
| 全部动作 | 48,177 | 49,215 |
| 移动动作 | 40,466（83.99%） | 35,297（71.72%） |
| 回到已见阵型的移动 | 39,033 | 6,420 |
| 相邻两步为逆向移动 | 37,068 | 2,208 |
| 冻结／解冻按钮次数 | 950 | 2,696 |
| 连续两次按冻结按钮 | 855 | 832 |
| 以冻结动作回到已见状态 | 855 | 1,266 |
| 完全相同的模型输入再次出现 | 39,421 | 7,037 |
| 回合数 | 851 | 951 |
| 被 60 次操作上限强制结束的回合 | **768（90.25%）** | **707（74.34%）** |
| 平均名次 | 3.65625 | 1.71875 |

这些是独立的诊断种子结果，不替换原来的 128 局独立评估。
回退次数包含重叠的重复访问，例如 A→B→A→B 会出现多次回到已见状态；
不同回合、不同对局，以及中间发生购买／打牌／刷新等其他操作的情况都不连接起来计数。

## 实际案例

确定性模式第 2 回合：

```text
阵型实体 ID：[11, 44]
Move 0 → 1  → [44, 11]
Move 1 → 0  → [11, 44]
```

该案例的完整输入（features、cards、合法性 mask）也回到原值。
仅在此存档副本去掉 60 次操作上限后，再运行固定的 128 步：**128 步全部是移动，
始终在上述两种阵型之间往返，只有两个不同的模型输入状态**。
这是有界诊断重放，不是对训练或原始评测规则的修改。
详见 [uncapped-replay.json](uncapped-replay.json)。

确定性模式第 1 回合另有冻结案例：

```text
未冻结 → Freeze → 全部冻结 → Freeze → 未冻结
```

12 个案例均从独立保存的原生 BatchEnv 存档重放：移动回退验证真实实体 ID 顺序，
冻结回退验证每张酒馆牌的冻结状态，而不只依靠近似卡牌特征。
原生 Move 语义是“移出再插入”，本例的相邻两格恰好表现为交换。

## 与实现相关的原因

- 当前网络没有自己的招募操作历史或循环检测状态；全局观测也不包含
  `actions_this_turn`、`freezes_this_turn`。在本例完全相同的输入下，argmax 重复给出相同动作。
- 训练奖励以终局名次为主，gamma=1，招募期这些操作没有单独的时间或点击成本惩罚。
  保持最终局面不变的额外动作缺少直接的负奖励。
- 第一次训练显式采用每回合 60 次操作上限，默认冻结／解冻按钮最多按 10 次。
  模拟器能继续推进、模型能取得较好名次，并不代表它在这些局面会主动及时结束操作。

第一点和第三点可直接从观测／动作实现与本次轨迹确认。
奖励设置说明了训练未直接优化操作效率，不代表本次诊断单独证明了训练因果关系。
