# 实验 01：PPO 小模型 TavernBench 评测

日期：2026-10-31，Asia/Shanghai。状态：**已完成**，官方 eval 集 368 题、40 个场景。
使用第 100 轮保留模型 `runs/20261031-ppo-small-100ppo-32minibatches/20261031-131146-best_model.zip`，
并用相同适配器测零步初始化。两份权重均未修改，也没有上传。

## 总分

Play 按官方的 **30 个可玩场景等权平均**，不是逐题正确率。

| 模型／策略 | 纯策略 Play | 策略 + combat256 Play | 23 个非战斗策略场景均分 |
| --- | ---: | ---: | ---: |
| PPO 训练前 | 18.3778% | 41.2944% | 23.9710% |
| **PPO 第 100 轮** | **20.9642%** | **43.8809%** | **27.3447%** |
| 原脚本适配基线 | 23.3046% | 46.2213% | 30.3973% |

训练前后使用相同任务、候选约束、动作序列评分和模型接口，Play 改善 **2.5865 个百分点**，
23 个策略场景均分改善 **3.3737 个百分点**。本次纯 PPO Play 比原脚本适配基线低 2.3404 个百分点。

combat256 是另行列出的同一个战斗组件：R2 与 B1–B6 用原脚本基线适配器的规则判定或
每题 256 次独立战斗模拟；策略题完全复用纯模型答案。两种 PPO 的 56 道战斗题均为 55 题正确，
该组件带来的分数不归入 PPO 本身的能力。

## 覆盖率与适配协议

纯 PPO 在 288 道 Play 题中有效作答 **227 题（78.82%）**；第 100 轮正确 70 题，零步模型正确 54 题。
加 combat256 后有效作答 **283 题（98.26%）**；正确题数分别为 125 和 109。
所有系统均保留完整 368 条回答，不支持或无法映射的题目继续计入原分母。
脚本纯策略正确 63 道 Play 题，但其宏平均 Play 高于 PPO；题量较多的 N 场景不会获得更高权重。

PPO 没有文本问答或战斗预测输出头：80 道规则执行问答不适用；纯模型另有 56 道战斗预测题不支持。
官方数值 `rule_score` 将未作答的规则题计零，不解释为模型直接回答了这些问题。
官方分类字段 `rules` 实际是可玩的一对一战斗 R2，与十个规则执行问答场景不同。

另有五道站位题（P1-002、P2-001、P2-002、P3-006、P5-005）存档中仍有 pending choice，
真实合法动作掩码只允许选择，不允许移动或结束回合。本次不清空 pending，不强行修改状态，
标记 `unmappable_task` 并计零；这与执行错误分开。该限制对训练前后相同。

适配协议在读取标签前固定，见 [protocol.json](protocol.json)：

- 模型只接收 `Game.observe(seat)` 的玩家视角数值／卡牌和真实动作掩码，不接收完整内部状态或正确答案。
- 将公开选项转成可执行的动作序列，在每个前缀上，把策略概率限制并归一化到候选允许的下一步；
  所有候选共有的强制动作概率为一，选取完整序列概率最高的选项。没有调用价值头搜索或战斗搜索。
- 站位选项使用从左到右恢复目标排列的规范移动路径，再接结束回合；购买序列也以结束回合表示停止购买。
  这是动作策略到选择题的适配，结果受路径定义与序列概率影响，不等同于专门训练的即时战斗价值预测。
- 顺序和目标题在副本执行题目指定操作，按实体 ID 重定位移动后的手牌／随从；所有模拟副本重新设种子。
- 英雄题还原公开 HeroSelect；自然对局的发现／回合计划使用存档指定的真实席位。
- 原脚本基线没有完整动作概率分布，使用其原先的启发式适配；两者接口处理不同。
  训练前后 PPO 是相同协议比较，脚本分数作为已记录的参考，不宣称接口和工具条件完全相同。

这是本地 PPO 的明确适配结果，不是论文 TavernAgent 的专用评测接口复现。当前模型对这些题未做微调。

## 验证与产物

全部预测先生成并保存 SHA-256，再读取冻结标签调用原版 `score_answer`、`report.evaluate` 和 `report.summarize`。
推理阶段用 Python audit hook 拒绝打开 labels.jsonl 和已发布参考答案；Rust 战斗组件仅接收 stdin 的公开输入。

- 4 个系统各 368 个唯一任务 ID；零适配器执行错误；5 个无法映射任务保留。
- 454 个有效模型选择题的完整候选概率和均为 1，最大误差约 6.2e-7。
- 站位动作执行后按实体 ID 核验最终排列；每个用于评分的动作均通过真实合法性掩码。
- 原有 Rust 适配器五项测试通过；标准报告与单独汇总分数一致。
- 答案、推理源码和模型摘要均复核，权重保持不变。
