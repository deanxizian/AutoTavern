# 2 脚本 + 3 V1 + 3 V2 整局对战

256 个八人对局，V1/V2 均为随机采样、BF16 前向，FP32 权重与概率。
使用实验 01 和实验 02 正式完成 100 PPO 后各自验证集选出的 best，SHA-256 见 config.json。
不训练、不修改权重、不使用推理动作筛选或战斗搜索。沿用每回合 60 次操作上限。

原生 BatchEnv 并行 64 局，每条 lane 连续记录最先完成的 4 局，淘汰后继续到同局全部模型席位结束，
不按单个学习者淘汰提前重置。席位随机轮换；V1/V2 的执行先后优先级在 lane 间平衡。
脚本使用原生默认策略，两个脚本的最终名次集合由六个模型席位之外的剩余名次精确计算，
不将这两个名次虚构对应到单个脚本席位。

- 吃鸡率：该组获得第一名的次数 / 该组玩家参赛次数。
- 第一名占比：该组获得第一名的次数 / 256；三组之和为 100%。
- 前四率与平均名次：按玩家参赛次数计算；V1/V2 各 768，脚本 512。
- V2 对 V1 名次胜率：每局 9 对跨版本席位中 V2 名次更靠前的比例；不是单场战斗胜率。
- 置信区间：以整局为单位做 10,000 次 bootstrap，避免把同局席位当成独立样本。

原始逐局结果保存到 games.jsonl，汇总保存到 results.json；W&B 使用独立评测 run，
横轴为 evaluated_lobbies，不写入已有训练曲线，不上传模型。

## 结果

北京时间 2026-10-31 19:15 完成，256 局，约 67.2 秒。两版模型均随机采样、BF16 前向，
每局始终为 2 脚本 + 3 V1 + 3 V2。256 个唯一 lane/episode 对均有完整 1–8 名次集合；
各 lane 恰好 4 局，原生拒绝动作 0 次，评测前后模型 SHA-256 一致，优化器更新 0 次。

| 策略 | 玩家参赛次数 | 第一名次数 | 每席位吃鸡率 | 前四率 | 平均名次 | 全部第一名占比 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| V1（3 席） | 768 | 87 | 11.33% | 58.85% | 3.9805 | 33.98% |
| V2（3 席） | 768 | 165 | 21.48% | 71.22% | 3.3763 | 64.45% |
| 脚本（2 席） | 512 | 4 | 0.78% | 4.88% | 6.9648 | 1.56% |

V2 对 V1 的同局最终名次胜率为 59.81%，按整局 bootstrap 的 95% 区间为 56.73%–62.89%。
V2 平均名次较 V1 改善 0.6042，改善区间为 0.3893–0.8138 名。
这是当前阵容的评估，不能直接外推到其他对手组合、贪心推理或单场战斗胜率。
若要正式确认，建议使用预先固定的新随机种子再做 1,024 局复核，避免根据早期胜负决定何时停止。
