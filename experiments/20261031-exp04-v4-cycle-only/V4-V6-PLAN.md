# V4–V6 三阶段训练计划与规则检查

2026-10-31（北京时间）。用户要求三版各 100 PPO，其余沿用 V3；随后确认
`ABABAB` 三组连续往返判负，并将超过 60 个动作也改成判负。本次实现规则和准备配置，尚未启动训练。

## 固定预算与衔接

| 阶段 | 来源 | PPO | 学习者样本 | Adam 上限 | 状态 |
| --- | --- | ---: | ---: | ---: | --- |
| V4 | V3 PPO150 best，已绑定路径与 SHA-256 | 100 | 13,107,200 | 1,600 | prepared |
| V5 | V4 选中的 best，可能仍是继承起点 | 100 | 13,107,200 | 1,600 | 等待来源绑定 |
| V6 | V5 选中的 best，可能仍是继承起点 | 100 | 13,107,200 | 1,600 | 等待来源绑定 |
| 合计 | 串行三阶段 | 300 | 39,321,600 | 4,800 | V6 完成即停止 |

每阶段继承完整 PPO 边界的网络和 Adam moments／历史计数，重启阶段计数，使用固定 LR，
不用清空 Adam 的 warm start，也不把上阶段 final 当成 best。
每阶段 128 环境 × 1,024 步，minibatch 8,192、16 个／PPO、microbatch 1,024、epoch=1。
V4、V5、V6 的 LR 全程固定为 `1e-5`，无 warmup、无衰减；仍继承所选 best 的 Adam moments 和历史计数。
配置沿用已有 linear 调度，起止值均为 `1e-5`，从每阶段第一次 Adam 更新起固定。
网络、BF16 前向／FP32 权重与 Adam、其余 PPO 参数与种子沿用 V3。

三阶段对手固定为 **2 固定 V1 + 3 固定 V2 + 2 脚本**，模型对手冻结且随机采样，学习者为第八席。
此次不采用方法论草案中改变对手池的晋级流程；统一的固定开发验证决定阶段 best 和下一阶段起点。
若起点未被严格改善，保留它，不把新的实验版本号宣称为新冠军。

V5／V6 不编造未来 best 路径、哈希、PPO 或 Adam 计数；未绑定来源时启动入口拒绝运行。
前一阶段完成后读取真实 best 的元数据，填入并冻结下一阶段配置。
角色配置与训练启动由用户安排的主 agent／subagent 链路承接；本次不创建独立监控 chat 或启动训练。

## 统一终止规则

`reward_shaping` 显式设置操作成本 0、全动作循环成本 0.0002、
`cycle_forfeit_repetitions=3` 和 `turn_action_forfeit_limit=60`。旧配置缺省关闭两个新终止条件。

reward 模块判断，外层环境执行：

1. **三次闭环**：使用完整模型可见 features/cards，忽略合法掩码，维护去除已闭合环路的状态路径。
   每次返回路径中的状态，完成一个闭环并去掉环路后缀。
   A／B 两个动作重复三组在第六个动作后触发；三动作菜单循环在第九个动作后触发。
   每次返回已见状态仍扣循环成本，不能把 `cycle_returns` 直接当成闭环数。
   切换到已见环路仍累计，遇到本回合未见的新可见状态则清零连续闭环数。
2. **动作超限**：每招募回合前 60 个动作允许执行；第 61 次策略动作请求在执行前直接判负，
   包括原本到上限后被强制选出的 End。不会先进入战斗后再按新名次判负。
   60 个动作以内主动 End 正常换回合。选择、取消、移动、冻结、技能均计入预算；英雄选择不计。
   pending 菜单不能绕过预算，新状态也不重置动作数。

真实跨回合、reset 清零动作计数；End、跨回合、reset、观测断续清空循环历史。
同回合跨 rollout 两种计数都保留。循环阈值发生在动作执行后，预算阈值发生在超限请求执行前，
两者不会给同一个转移发两次奖励。

原生通用淘汰接口不包含循环或步数阈值，不添加模型可选动作。
它复用正常名次、卡池归还和淘汰效果流程。含自身剩 N 人时判负为第 N，按原名次效用发一次奖励，
不伪造第八或额外 −1。`done=True`、`TimeLimit.truncated=False`，GAE 不跨局、名次辅助标签一致。
角色旋转按逻辑学习者定位，不能误淘汰物理 seat 0；冻结 V1／V2 和脚本不套学习者新规则。

## 验证、晋级和留存

每阶段 PPO 0／50／100：**2 固定 V1 + 3 固定 V2 + 2 脚本，学习者随机／贪心各 64 局**，
所有模型 BF16 前向，固定对手随机。只有随机组平均名次严格降低才替换 best，相等保留较早版本。
不跑额外七脚本对照，不把 Greedy、判负率或吃鸡／前四率加入选模。

initial／best／final 独立评估使用相同混合阵容，**学习者随机／贪心各 128 局／模型**，
不参与选模或晋级。起点在新规则下重评；原 V3 历史验证和 test 不回写。
W&B 每版独立 run，train 横轴是阶段实际 Adam 次数，val 从 step=0 开始。
记录来源、固定对手的版本／路径／哈希／精度、配置与代码摘要。

保留阶段时间戳 best 和所有仍被引用的来源；独立评估完成前不清理 initial／final。
意外中断只用完整 PPO 检查点恢复原阶段、原配置和 W&B；先保留现场，未知故障先诊断，
最多恢复一次，用户明确停止不得恢复。总预算 300 PPO，V6 最终评估完成后停止，不追加版本。

## 风险与处理

1. **阈值歧义**：用户最终确认三组，弃用此前“四次”建议；测试覆盖第六／第九动作和第 60／61 请求边界。
2. **终局不一致**：仅改 reward 或 Python done 会使原生状态、辅助名次和采样冲突；两种原因都走真实淘汰。
3. **后期早退获正奖励**：剩四人时第 4 奖励为 1/7，剩两人时第 2 为 5/7。
   这是按当前输掉的结算含义，可能形成早退偏好；本轮不擅自追加 −1 或修改选模。
   必须联合观察两种判负率、回合、名次与总动作数，不能只看循环均值下降。
4. **可见等价不等于完整状态等价**：隐藏 RNG／计数器可能改变；不能断言所有可见重复无收益。
   不断制造未见状态可绕开连续闭环阈值，但仍受独立 60 动作预算约束。
5. **短局改变样本分布**：100 PPO 按策略转移预算；操作超限请求计一次终局转移，
   并明确它没有执行正常游戏动作。判负会增加完成局数，局数增长不代表实力提升。
6. **历史比较不公平**：V3 旧检测器和强制 End 规则下的循环、名次不直接与 V4 比；
   用 V3 权重作为 V4 起点重评，冻结对手保持原规则。随机与 Greedy 分开解释。
7. **重复使用开发验证**：沿用 V3 种子符合本轮要求，但多阶段增加适应验证集的风险；
   独立 128 局 test 只报告。后续改种子／对手需另开协议，不能覆盖历史。
8. **来源 Adam 不能推算**：best 可能在 PPO0／50／100，下一版读取实际检查点计数，不能每代机械加 1,600。
9. **指标分母**：`cycle_forfeit_rate` 和 `action_limit_forfeit_rate` 是完成局比例；
   对应 turn／placement 标量对未触发局填零，其全局均值除以对应 rate 才是触发局条件均值。
   `cap_end_rate` 只记实际强制 End，超限判负另记，避免混淆。
