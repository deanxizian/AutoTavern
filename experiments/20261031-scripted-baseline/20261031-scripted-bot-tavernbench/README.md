# 脚本机器人 TavernBench 基线

- 日期：2026-10-31，Asia/Shanghai。
- 状态：已完成。
- 主评测集：官方 `data/eval`，368 题、40 个场景；Play 按论文的 30 个游戏决策场景取平均。
- 不训练、不调参，不修改机器人或冻结标签。先生成并封存答案，再用官方评分器评分。

## 预先确定的评测协议

脚本机器人没有通用问答接口。此处报告的是**内置启发式在题目约束下的适配基线**，不能视为一个原本就能回答全部题目的模型。

本次逐题使用同一套脚本启发式，没有引入多样化机器人策略。默认环境中的七个脚本对手共用这套决策代码和参数；八机器人演示也使用同一策略控制全部席位。不同英雄和局面会产生不同动作，但不代表存在七种不同策略，也没有在线学习。论文中的七个现实校准库对手属于另一种配置，详见[统一说明](../../README.md#默认脚本机器人说明)。

同时记录两个系统：

1. `scripted-policy`：仅使用原有启发式。没有规则问答和战斗预测接口的题目明确标为不支持，在全量分母中计 0；另行报告作答覆盖率。
2. `scripted-combat256`：策略题与前者完全相同；仅对 R2 与 B1–B6 七个战斗预测场景，额外使用规则判定或 256 次重新设种子的独立战斗模拟。模拟器贡献单独列出，不归入机器人的策略能力。不对候选动作搜索胜率，也不做整局前瞻。

两个系统都不回答十个规则执行场景；Rules 分数应解释为不适用，而不是机器人规则执行能力为零。

| 题型 | 策略适配方式 |
| --- | --- |
| 站位 P1–P5 | 机器人没有移动站位逻辑，选择保持当前顺序的选项。 |
| 顺序 O1–O5 | 在题目要求执行的操作中，沿用机器人按手牌从左到右打出可用卡牌的优先级；需要腾位置时按原有 `minion_value` 选择最弱的待售随从。执行状态变化后重新解析位置，避免手牌移动导致索引错位。 |
| 目标 T1–T3 | 先执行题目指定的法术、主动能力或英雄技能，再直接调用机器人处理目标选择。 |
| 磁力 T4 | 沿用原机器人选择第一个合法宿主的规则。 |
| 出售 T5 | 沿用原机器人出售估值最低随从的规则。 |
| 购买 E3 | 仅在题目允许的购买并立即打出操作中，沿用随从估值与配对加分，依次选择可负担的牌；不加入升本、刷新或其他操作。 |
| 英雄 D1 | 使用机器人原有随机选择；从题目候选状态恢复英雄列表，以任务 ID 派生固定随机种子。 |
| 饰品 D2、发现 D3、自然选择 D4 | 直接调用机器人处理对应候选；自然对局使用存档指定的真实席位。 |
| 手牌选择 D5 | 沿用机器人从左到右选择首个可打出的手牌的优先级。 |
| 回合计划 N1–N2 | 将机器人的原始下一动作映射到题目候选；如果它想做的动作不在候选中，明确记为无法映射，不擅自添加价值模型或随机答案。 |

适配器仅接收题目 ID、场景、已保存状态和候选操作；候选项中的 `answer` 是选项编号／字母，不是正确答案。推理阶段不读取 `labels.jsonl`，也不读取作者或其他模型的答案。所有不支持、动作无法映射、执行错误均逐题保留，不删除后重新计算分母。

固定每题随机种子，战斗样本每次从原始状态独立复制并重新设种子；不使用副本中的既定未来。当前模拟器含论文发布后的规则修复，评分仍使用原始冻结标签。

## 结果

使用官方 `tavernbench.report` 和 `score_answer`，不修改评分函数。Play 按 **30 个场景等权平均**，不是把 288 道题的正确数直接相除。

| 系统 | Play | Play 有效作答 / 288 | Play 覆盖率 | 正确题数 / 288 |
| --- | ---: | ---: | ---: | ---: |
| 启发式策略适配 `scripted-policy` | **23.30%** | 185 | 64.24% | 63 |
| 同一策略＋战斗预测 `scripted-combat256` | **46.22%** | 241 | 83.68% | 118 |

两个系统在共同的 **23 个策略决策场景**上答案完全相同，这部分的场景均分为 **30.40%**；其中保留了所有无法映射题的零分。两组总 Play 的差额全部来自七个战斗预测场景，没有对站位、顺序、目标或购买做战斗搜索。

| 分项（场景均分） | 策略适配 | ＋战斗预测 |
| --- | ---: | ---: |
| 一对一战斗 R2 | 不支持，计 0 | 100.00% |
| 战斗 B1–B6 | 不支持，计 0 | 97.92% |
| 站位 | 25.00% | 25.00% |
| 操作顺序 | 32.50% | 32.50% |
| 目标选择 | 37.50% | 37.50% |
| 选牌／英雄／饰品 | 37.50% | 37.50% |
| 回合计划 | 12.07% | 12.07% |
| 购买决策 E3 | 12.50% | 12.50% |
| 十个规则问答场景 | 不适用 | 不适用 |

### 覆盖率与限制

- 两组均保留 368 条答案记录，所有题都在评分分母中；80 道规则问答未作答，且不属于 Play。
- 纯策略另外不支持 56 道战斗预测题。带模拟器版本回答了这 56 道，正确 55 道；B6 有一道未通过官方概率答案阈值。
- **47 道回合计划题无法映射，均计 0**：N1 为 20/29 道，N2 为 27/27 道。机器人经常想先打手牌、出售或买另一张牌，而题目只给“购买指定牌／刷新／结束／升本”四个首动作。机器人没有能对这四个受限选项重新评分的策略分布或价值头，本实验没有事后增加一种选择规则来补分。
- 这是已明确适配协议下的保守基线，尤其受 N1/N2 接口覆盖限制；不应把无法映射等同于机器人在完整游戏中必然做了坏决策。
- 带战斗预测版本的 46.22% 包含模拟器能力，不能称为纯脚本策略成绩。它也没有复刻论文 TavernAgent 在短期决策题上使用的候选项模拟搜索。
- 本实验覆盖论文统一比较的 368 题子集，尚未测完整 960 题集。

JSON 中 `rule_score` 是官方评分器将未作答题记零的原始值，应按 `rules_applicable=false` 解释为不适用；官方汇总字段 `rules` 实际是可玩场景 R2 的一对一战斗分项。`answered_scenario_mean` 只是在已作答题内重新计算的诊断值，会改变分母，不作为主基线成绩。

### 已发布答案的参照

用同一评分器复算仓库已发布的 eval 答案，得到 TavernAgent **91.44%**、GPT-6 Astra **63.16%**、Claude Opus 5.5 **51.88%**、Jev **37.00%**。这些系统的输入接口和工具权限不同，列在这里作为结果定位，不代表控制了工具使用的同条件比较。

## 验证与可复现性

- 五项适配器测试通过：实体 ID 与手牌索引移动、原生目标偏好、未列出动作不虚构答案、保持原始站位、独立战斗采样的可重复性及输入不变性。
- 368 个任务 ID 无缺失或重复；无原生进程 panic、无适配器执行错误；不支持与无法映射均与执行错误分开。
- 答案在读取标签前写入文件并计算 SHA-256；评分后再次核对哈希。机器人源码未修改。
- 两组非战斗题的回答、状态与选择轨迹一致；战斗模拟没有出现截断。
- 输入数据、适配代码、机器人代码、答案文件及已发布参照答案的哈希均已记录。

从仓库根目录运行：

```bash
python experiments/20261031-scripted-baseline/20261031-scripted-bot-tavernbench/run.py
```

不需要模型 API 或额外 Python 包，使用 Python 标准库和项目固定的 Rust 1.98.1。Rust 依赖按 `Cargo.lock` 离线构建，需先备妥工具链及依赖缓存。若 PATH 中没有 Rust，脚本会尝试本次已经安装的 `/tmp/autotavern-cargo` 与 `/tmp/autotavern-rustup`。重复运行保存在 `reruns/` 中，不覆盖原始答案。

仅复算本次已保存答案，可从仓库根目录执行：

```bash
cd tavernbench
python -m tavernbench.report --set data/eval \
  --runs ../experiments/20261031-scripted-baseline/20261031-scripted-bot-tavernbench/answers \
  --systems scripted-policy,scripted-combat256
```
