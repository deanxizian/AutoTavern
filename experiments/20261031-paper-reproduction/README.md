# 论文吞吐量与接口复现

- 日期：2026-10-31，Asia/Shanghai。
- 状态：已完成。
- 目的：验证论文报告的单核整局与后期战斗速度，以及动作、观测、批量运行和精确存档恢复接口。

## 方法

使用仓库原始的 `crates/taverngym/examples/bench.rs`，不修改引擎或基准代码。Release 构建，使用工作区默认优化配置，未添加 `target-cpu=native`。运行进程绑定逻辑 CPU 0，单线程，默认 36.6.3 规则，八个内置启发式机器人，关闭事件日志。

预热 200 局及 20,000 场战斗，不计入正式结果。之后顺序运行三轮，每轮 2,000 局（种子 0–1999）及 20,000 场战斗。编译和控制台输出不计入基准内部计时。每次操作延迟由基准输出的吞吐量换算。

战斗样本严格沿用原始基准：取种子 0 完整游戏结束后的快照，将各玩家标记为存活、将其最后阵容复制为当前阵容，再反复运行指定配对。该样本不代表所有后期阵容的耗时分布。

环境：AMD Ryzen 7 9700X，WSL2 虚拟化环境，Rust 1.98.1。完整 CPU 信息见 [lscpu.txt](lscpu.txt)，代码提交与源码哈希见 [benchmark-results.json](benchmark-results.json)。

## 吞吐量结果

| 轮次 | 完整八人游戏 / 秒 | 毫秒 / 局 | 战斗 / 秒 | 微秒 / 场 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 370 | 2.703 | 104,400 | 9.579 |
| 2 | 375 | 2.667 | 103,591 | 9.653 |
| 3 | 374 | 2.674 | 104,887 | 9.534 |
| 中位数 | 374 | 2.674 | 104,400 | 9.579 |
| 论文范围 | 190–280 | 3.6–5.3 | 52,000–76,000 | 13–19 |

本机测得的速度超过论文报告的范围，支持该实现达到论文所述吞吐量级。硬件、虚拟化环境、代码版本和战斗样本可能不同，因此不能视为对原始硬件条件下精确数值的复现。

## 复现命令

从仓库根目录执行：

```bash
cargo +1.98.1 build --release --locked -p taverngym --example bench
python experiments/20261031-paper-reproduction/reproduce_bench.py
```

脚本需要 Linux 的 `taskset`，从进程允许使用的 CPU 中选择编号最小的一个。原始测量数据位于 [run-1.txt](run-1.txt)、[run-2.txt](run-2.txt)、[run-3.txt](run-3.txt)，预热输出位于 [warmup.txt](warmup.txt)。

再次执行脚本时，新结果保存在 `reruns/` 下按时间命名的子目录中，不覆盖本次原始记录。

## 接口验证

仓库现有的 **27 项定向测试全部通过**，原始输出见各 `tests-*.txt`，结构化汇总见 [interface-results.json](interface-results.json)。

| 测试组 | 通过数 | 主要覆盖 |
| --- | ---: | --- |
| Rust 单元测试 | 15 | 245 个动作的编解码、批量运行、线程数独立性、存档恢复、随机数确定性等。 |
| 整局测试 | 6 | 完整排名、相同种子的确定性、状态序列化、随机合法动作及状态不变量。 |
| 合法动作掩码 | 1 | 12 个种子中抽样的掩码合法动作不会被执行接口拒绝。 |
| 玩家视角观测 | 3 | 隐藏未交战对手当前阵容、保留上次交战阵容、显示待选来源与相关状态。 |
| 公开排名信息 | 2 | 公共信息不泄露对手当前卡牌，种族等汇总正确。 |

此外，通过 [verify_trajectories.rs](verify_trajectories.rs) 补充了端到端检查，结果见 [trajectory-verification.json](trajectory-verification.json)：

- 与基准相同的 **2,000 个种子全部自然结束**，排名均为第 1–8 名；没有驱动停止、回合上限结束、战斗截断或招募效果截断。
- 实测接口尺寸为 **245 个动作、3,227 个数值特征、124 个卡牌索引**。
- 两局游戏实际推进至第 **8 回合**后存档，恢复到另一批量环境；原环境使用 1 个线程，恢复环境使用 3 个线程。
- 继续执行 **200 次批量 step（每个环境 400 个动作输入）**，期间出现 20 次席位 episode 结束；两边每步状态、观测、奖励和名次完全一致，动作拒绝数为 0。

这支持 Rust 引擎层面的动作、观测和批量保存／恢复能力；这些定向测试不是对官方客户端全部可见字段或全部卡牌交互的穷尽验证，也未在本次实验中测试 Python 绑定。

从仓库根目录复现接口检查：

```bash
python experiments/20261031-paper-reproduction/reproduce_interfaces.py
```

脚本运行现有 Rust 测试，并将补充检查链接到已编译的 Release 引擎。如果系统 PATH 中没有 Rust，会尝试使用本次已安装到 `/tmp/autotavern-cargo` 和 `/tmp/autotavern-rustup` 的独立工具链；其他机器应先安装项目固定的 Rust 版本。
