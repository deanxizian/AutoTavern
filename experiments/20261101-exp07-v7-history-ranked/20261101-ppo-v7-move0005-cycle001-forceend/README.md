# V7 移动成本准备方案

2026-11-01 用户确认：针对 V5 不断换站位的问题，移动扣分方案首先放入 V7；仍然只准备，不启动训练。
本目录是新准备版本，之前因用户停止而中断开发排名的 V7 目录、实例 manifest 和已封存证据保持原样。

## 奖励方案

| 项目 | V7 准备值 | 含义 |
| --- | --- | --- |
| `move_cost` | `0.0005` | 每次实际成功的招募阶段 Move 固定扣分，无免费次数 |
| `operation_cost` | `0` | 保留现状，不借旧的 Move／Freeze 联合费用处罚冻结 |
| `cycle_cost` | `0.01` | 返回同回合已见完整可见状态的额外扣分 |
| `cycle_detection` | `all_actions` | 沿用现有完整可见状态检测 |
| 两种 forfeit 阈值 | `null` | 不因循环或预算提前判负 |
| `turn_action_caps` | `[60]` | 达预算仅强制 End；本轮不放宽上限 |

一次移动同时命中循环返回时合计扣 `0.0105`。正常调整 3 次仅移动费用 `0.0015`，
移动 60 次费用 `0.03`。这些是拟定规则的算术量级，不是已验证的训练收益。
移动有战术价值，加入成本可能导致少调位或过早 End，须靠独立开发评估检查。

费用由 reward 层实现，不放入模型外壳作动作过滤，不改变原生合法掩码或模型输入。
Freeze、买卖、出牌、菜单选择和 End 不加移动费；循环返回仍依原规则单独处罚。
只计实际执行成功的 Move，deferred、拒绝、未执行的预算拦截不计；真实执行 Move 后即终局仍要收费。

## 来源、阵容与预算

- 按用户最新指令，直接继承 **V5 所选 best 的完整 PPO／Adam**，固定 LR=`1e-5`；只读核验见 [planned-source.json](planned-source.json)。
- V4、V6 虽各训练过 100 PPO，但保留 best 与继承起点的策略/Adam 相同，分别作为 V3、V5 的废弃别名，不用来占新对手池席位。
- 生命周期清单见 [model-versions.json](../../../configs/model-versions.json)；新候选为 V1／V2／V3／V5，V0 单独作为脚本。保留旧 V4／V6 权重与完整历史，不物理删除。
- 对手仍为独立开发排名中最强三个历史版本各两席，加一个 V0；学习者是第八席。
- 排名未完成，因此不在此稿擅自写死前三，也不用旧 320 局独立测评挑池；冻结对手保留各自来源奖励协议，缺 `move_cost` 等同 0。
- 配置沿用原 V7 的 100 PPO、每轮 131,072 样本、最多 16 Adam 更新等准备值；100 PPO 只是准备预算，不构成重新启动授权。
- 曾讨论的“两臂各 25 PPO”仅是评审建议，本轮没有创建或授权该实验；此处只准备 V7 单阶段。
- 不自动启动 V8／V9，不恢复已停止的控制器，不修改 V1–V6 或旧 V7 配置。

配置故意保持 `initial_model=null` 和未绑定对手池，防止把准备误当完整运行实例。
后续明确启动时，须在新实例中完成开发排名、来源/池绑定及检查；不是修改旧实例并恢复。

## 验证与采纳

新增配置缺字段默认 `move_cost=0`，旧奖励行为保持；费用和 `move_actions`、`move_penalty`、
每局 `move_action_fraction` 进入 train／val／greedy 指标。
回归覆盖移动单独收费、与循环叠加、Freeze 不收移动费、终局动作、reset、deferred 及旧配置兼容。
起点须在 V7 规则下重新评估；best 仍只按混合随机验证平均名次严格改善替换，不按罚分变小选模型。
同时报告吃鸡率、Top 4、逐回合移动和总动作分布、主动/强制 End、状态返回以及结束时可用资源等诊断，
检查是否通过过早结束或改为其他无效动作来减少移动罚分。额外资源诊断需有实际采样证据，不能宣称旧日志已有。

本轮仅实现与回归检查，不产生新的 PPO 训练、开发比赛或 W&B 训练 run。
