## 配置与论文边界

下次启动采用 [config.json](config.json)；上次启动时的配置快照见 [resolved-config.json](resolved-config.json)。
上次仍为 microbatch=256，新默认为 1,024，原始计时和历史快照保留原值。

| 参数 | 当前实验 |
| --- | --- |
| 网络 | d=192、4 层、8 头、FFN=1024，3,491,978 个可训练参数 |
| 迭代 | 300 |
| 每轮采样 | 256 个环境 × 每环境 16,384 步 = 4,194,304 个决策 |
| 有效 minibatch | 8,192 |
| microbatch / 梯度累积 | 默认 1,024 / 8；已有三轮为 256 / 32，完整 minibatch 后裁剪梯度并更新一次 Adam |
| epochs | 1；目标 KL 超过阈值时提前停止该轮更新 |
| 学习率 | 线性 `6e-6 → 5e-6`，计划按整个 300 轮的采样进度推进 |
| γ / GAE λ | 1.0 / 0.995 |
| clip / target KL | 0.2 / 0.05；沿用 SB3 的 1.5 × target KL 停止判据 |
| 熵 / 价值 / 名次辅助系数 | 0.002 / 0.5 / 0.1 |
| 梯度裁剪 | 1.0 |
| 随机种子 | 42 |
| 对手与奖励 | 七个相同脚本策略；终局线性名次效用，第一 +1、第八 −1 |
| 每回合动作预算 | 60；达到预算后由模拟器限制为结束回合及必要待选动作 |

默认值变更和全量时间重估见
[config-changes/microbatch-1024/README.md](config-changes/microbatch-1024/README.md)。
300 轮使用新默认时，允许 TF32 的 FP32 方案粗估 52–54 小时；BF16 混合精度方案粗估 39–42 小时。
BF16 当前仅在独立基准中启用，正式训练配置仍为允许 TF32 的 FP32；本次只修改 microbatch 默认值，没有恢复训练。

论文明确提供早期实验的模型规模、400 轮和每轮约 420 万决策。
早期完整超参数与规则简化过程未公开，因此学习率端点、minibatch 和若干系数参考最终阶段表 7，
线性曲线、环境数量／步数拆分、FFN、文本编码器和指针公式属于本地实现选择。
这不是论文原始早期配方的完整复现。首次从零训练没有前一阶段 KL 锚定，
也未复现论文的校准对手库与完整输入字段。
每回合 60 动作是本地驱动约束，用于防止移动、冻结等零成本操作无限循环；
模拟器默认没有该上限，内置脚本机器人自身也会限制操作数。
初始确定性评估曾遇到这种循环，该次尚未采样或更新，记录保留在
`attempts/initial-deterministic-evaluation/`。后续训练与评估均采用相同的 60 动作预算。

SB3 在采样后调用学习率函数：前 3 轮使用原 400 轮调度；后续按 300 轮目标调度，终点为 `5e-6`；
开始采样前优化器 LR 为 `6e-6`。microbatch 不推进调度器。

## 无损缓存压缩

3,227 个数值特征中，677 个数值维保持 float32，2,550 个原生 0/1 标记按位存储；
124 个卡牌 ID 使用 uint16，245 个合法动作标记按位存储。

| 项目 | 每条字节 |
| --- | ---: |
| 数值维 | 677 × 4 = 2,708 |
| 二值维 | ceil(2,550 / 8) = 319 |
| 卡牌 ID | 124 × 2 = 248 |
| 动作掩码 | ceil(245 / 8) = 31 |
| 合计 | **3,306** |

原始观测为 13,649 字节／条，无损压缩约 **4.13 倍**，整轮观测 **12.914 GiB**。
另外保存奖励、旧概率、值、优势和辅助标签等少量数组。
缓存只保留当前轮，更新完成后覆盖复用；不保留 300 轮观测。
解包只读取当前 minibatch，不复制完整缓存，也不做 float16 量化。
磁盘版作为可选实现保留，当前实验使用压缩后的 RAM 缓存。

## 预检和验证

12 项学习／扩展测试通过，包括：真实观测 float32 位模式逐项还原、卡牌与掩码还原、
原始／磁盘／压缩缓存的相同采样与更新、梯度累积数值等价、跨线程确定性与自然终局。
梯度累积比较容差为参数 `rtol=5e-5、atol=2e-6`，并按完整有效 batch 归一化优势及辅助标签损失。
固定种子的评估结果可复现，且不会改变训练的 Torch 随机流。

预检从初始化副本开始，独立采样 32,768 个决策，完成 2 轮小采样量更新；
有效 batch 仍为 8,192，microbatch=256。GPU 峰值分配约 **1.45 GiB**。
第二轮测得约 6,032 决策／秒，第一轮约 4,077 决策／秒（含采样与更新，不含评估及保存）。
这是短时吞吐预检，完整训练耗时以实际完整轮测量为准。

## 评估与进度

- 开始前，用固定独立种子对初始化策略评估 128 局。
- 每 10 轮评估 128 局，报告平均名次、第一率、前四率，并保存平均名次最好的模型。
- 每个评估槽位有固定对局配额，避免先结束的对局在统计中占比过高。
- 完成后，再用另一组未用于选模的种子评估 256 局。
- 评估对手仍是脚本机器人，指标不能直接等同论文主测试／更难测试。
- 评估采用固定随机种子的策略采样，并保存／恢复训练的 Torch 随机流；不使用贪心动作。
- `progress.json` 每约 5 秒更新采样进度，完整轮更新后追加 `metrics.jsonl` 并保存 `latest_model.zip`。
- 每 10 轮保留一个定期检查点。中断时保存 `interrupted_model.zip`；它可能处于未完成的 rollout 中。

## CPU / GPU step 分项计时

见 [profiling/steps.json](profiling/steps.json) 和
[profiling/profile_steps.py](profiling/profile_steps.py)。独立运行，256 个环境，预热 16 步，
测量 128 个批量 step（32,768 个决策）；不计入正式预算。

| 阶段 | 平均毫秒／批量 step |
| --- | ---: |
| CPU 动作掩码准备 | 0.20 |
| 观测 H2D，含同步 | 0.39 |
| 策略前向，CUDA event 区间 | 6.36 |
| 策略前向，同步墙钟 | 6.38 |
| 动作 D2H | 0.07 |
| CPU 模拟器 step＋生成新观测（4 线程） | 6.87 |
| 无损压缩与缓存写入 | 1.71 |
| 完整批量采样 step | **15.62** |

完整 step 的 P95 为 18.83 ms，平均摊销为 61.02 微秒／玩家决策；
摊销量不等于 batch=1 的推理延迟。CUDA event 区间包含 kernel 启动间隙，
不是所有 kernel 纯执行时间之和；这些阶段当前按依赖串行执行，未声称 CPU/GPU 已重叠。
对这 32,768 个决策执行 PPO 更新，4 次有效 batch=8,192 的 Adam 更新共 3.28 秒，
每次约 0.82 秒；每次内部包含 32 个 microbatch=256 的梯度累积。
