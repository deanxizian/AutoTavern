# 默认 microbatch=1,024 与 300 轮耗时重估

2026-10-31，Asia/Shanghai。按用户要求将默认 microbatch 从 256 调整为 1,024；
有效 minibatch 仍为 8,192，梯度累积从 32 次变为 8 次，每个有效 minibatch 更新一次 Adam。
新默认已写入 EntityPPO、新建模型模板、通用训练入口和本实验 config.json。
初始化模板自身 batch=256，所以实际切片最多为 256；正式实验才是 1,024 × 8。

已有三轮检查点、初始化权重和上次运行的 resolved-config.json 保持原样，正式训练仍停止。
旧配置和预算已保存为 previous-config.json、previous-budget-estimate.json；变更记录见 [change.json](change.json)。

## 样本和更新预算

| 单位 | 样本量 | microbatch 数 | Adam 更新次数上限 |
| --- | ---: | ---: | ---: |
| 一个 microbatch | 1,024 | 1 | 每 8 个执行一次 |
| 一个有效 minibatch | 8,192 | 8 | 1 |
| 一轮 PPO | 4,194,304 | 4,096 | 512 |
| 完整 300 轮，统一使用新默认 | 1,258,291,200 | 1,228,800 | 153,600 |
| 从已完成的三轮继续，剩余 297 轮 | 1,245,708,288 | 1,216,512 | 152,064 |

实际前三轮使用 256，因此如果后续从三轮检查点继续，混合历史下总 microbatch 数为
49,152 + 1,216,512 = 1,265,664。以上均按 epoch=1、没有 KL 提前停止计算。

## 全量时间

两种精度均按 microbatch=1,024 外推：

| 方案 | 每轮采样 | 每轮 PPO 更新 | 每轮合计 | 完整 300 轮 | 剩余 297 轮 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 当前正式入口：FP32 存储、允许 TF32 | 249 s | 373 s | 10.37 min | 51.9 h | 51.3 h |
| BF16 autocast + FP32 概率、损失和 Adam | 239 s | 234 s | 7.88 min | 39.4 h | 39.0 h |

主表采用逆序补测的相对速度；再用初测独立外推，完整 300 轮分别为 53.6 h、42.1 h。
因此可暂按 **当前方案 52–54 小时、BF16 方案 39–42 小时** 做时间预算。
这些范围来自两次测量的波动，不是统计置信区间。

BF16 目前只在独立基准中测试，尚未接入正式训练入口，不能把 39–42 小时当成当前配置直接启动后的耗时。
本次没有启动或恢复训练。

## 依据与计算

- 既有三轮真实采样平均 249.37 s；更新平均 369.66 s，已扣除第二轮的 72.04 s profiling 暂停。
- 同一次基准中的 1,024 / 256 更新耗时比，用于缩放完整更新阶段；不是拿驻留 GPU 的小 batch 耗时直接乘 512。
- BF16 采样估计只扣除 16,384 个批量 step 的前向延迟差，模拟器、CPU 编码和压缩写入仍保留原耗时。
- 范围分别使用 FP32→BF16 顺序和逆序测量计算，固定同一份三轮检查点、8,192 条样本及 Adam 状态。
- 排除额外评估、检查点保存和中断；未来游戏长度、CPU 解包及 H2D 开销变化会影响实际时间。
- 本次没有运行完整一轮 1,024 配置；所有整轮和全量结果均为外推。

输入、公式和源码哈希见 [estimate.json](estimate.json)。可只重算预算，不启动训练：

```bash
uv run --locked --group train --extra test \
  python experiments/20261031-ppo-small-paper300/config-changes/microbatch-1024/reestimate.py
```

该脚本同时更新本目录 estimate.json 和正式实验 budget-estimate.json，不修改模型或训练状态。
没有本地 progress.json 时，从已提交的 experiment.json 读取完成轮数，可在新克隆中重新计算。

## 存储

整轮采样缓存仍约 13.07 GiB CPU RAM，循环复用；累计观测处理量约 3.78 TiB，不会全部落盘保留。
microbatch=1,024 的测试峰值 PyTorch GPU allocated 为：允许 TF32 的 FP32 约 5.12 GiB、BF16 约 3.74 GiB。
这是独立性能测试进程的分配峰值，未包含桌面和 CUDA 上下文的整卡占用。
权重继续保存在 runs，实验配置、变更及估算保存在 experiments。
