# V0/V1/V2/V3/V5 招募回合诊断补测

本目录是用户要求校正存活时长后的新测评，固定320局；不是旧320局的回放或补写。
十种八人阵容各32局，每个版本每局1–2席，累计各512次玩家出场。
V1/V2/V3/V5沿用旧测评冻结best及SHA-256，全部随机采样、BF16前向、FP32参数；V0为原生脚本。
不训练、不更新模型，不用结果选模或选训练对手池。

所有320个lane同时进入一个调度：192局六模型席位与128局七模型席位组成两个BatchEnv。
每个global round先合并两分片中同模型的全部ready玩家，只调用一次该模型predict，随后分发动作推进两分片。
完成局即时停用，每lane仅首局，无额外补局。原生turn_action_caps=[60]只强制End，不提前判负；
pending菜单可越过常规动作预算，不把大于61动作的回合判为错误。

每回合分母是玩家仍存活且被observe为ready时观测到的唯一招募回合编号（turn>0）。
该回合若因同批其他操作导致deferred或淘汰而没有执行动作，也保留0动作记录。
实际操作含End、出牌、菜单等接受的模型动作，不含deferred/rejected、自动战斗及V0操作。
turn=0英雄选择另列，不进入每招募回合动作数。终局后的自动reset观测不进入统计。

必须区分两个口径：

- 全体玩家回合加权：招募总动作数/玩家招募总回合数；player-turn分布每个玩家回合权重相同。
- 每玩家局等权：先计算该玩家整局招募动作数/其招募回合数，再对512次玩家出场求均值及分位数。

results.json的by_turn按实际游戏回合编号分别保存各模型样本数、均值与分位数，可控制早晚经济差异。
所有分位数使用排序后位置(n-1)p线性插值。没有置信区间，不将同局多席视为独立样本。

重复统一采用ActionRewardShaper的all_actions可见状态返回；operation_cost=cycle_cost=0，
两种forfeit阈值均为null，只观察而不改奖励、动作、输入或淘汰规则。End、终局及跨回合转换清空循环历史。
每次操作后的features/cards来自批环境推进后的公开观测，可能含同批其他席位及原生V0的公开变化；
与现有奖励检测器的批环境观测口径一致。动作ID同回合再次出现另列，不能解释为可见状态重复。

V0自动在Rust内执行，当前Python接口无逐操作回调；其步数、回合数和重复指标未知。
V0最终名次仅是模型名次的无序补集，不能对应到具体V0席位的个体名次。

留存文件：config.json冻结协议与来源；schedule-initial.json保存初始分片与lane映射；
games.jsonl保存320局完整排名；players.jsonl保存每玩家整局动作/回合/重复汇总；
turns.jsonl.gz保存每个玩家回合记录及有序动作、前后状态SHA-256等轻量轨迹（字段见config.trace_format）；
batches.json保存每次模型合并调用的round/batch大小/参与分片数；results.json保存统计与性能；
verification.json从封存轨迹独立重算统计、状态返回、批量配额与来源哈希。
哈希轨迹支持计数/循环审计，不含还原完整图形状态所需的所有原始观测。

开赛前preflight.py做合成统计检查；原生小规模校验执行两次，每次两个lane共5轮、65动作（合计130动作），均未完成额外比赛。第二次用于复核新增的single-End-mask轨迹字段。验证检查自身的边界修复见validation-history.json，正式320局只运行一次。
正式运行前拒绝已有experiment.json；失败现场保留，不自动重跑或换种子。

W&B：[在线测评](https://forge.coreweave.com/wandb/eric_eric_/AutoTavern/runs/y64dw1kt)，横轴完成局数。
