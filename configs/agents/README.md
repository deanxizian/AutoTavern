# RSI 总控、训练监控与测评 subagent

主 agent 按用户要求调用项目角色，训练需要持续监控时再拉起监控，模型对战使用测评角色：

```text
主 agent
├── orchestrator：gpt-6.1-sol / high，RSI 全链路总控
├── training_monitor：gpt-6.1-terra / medium，每 180 秒巡检并向主 agent 汇报
└── evaluator：gpt-6.1-terra / medium，冻结模型比赛、全量批量推理和独立核验
```

运行时角色位于 `.codex/agents/orchestrator.toml`、`.codex/agents/training-monitor.toml`
和 `.codex/agents/evaluator.toml`；本目录保留内容一致的可安装副本。
修改角色后同步这两处。无需为每个角色新建独立 chat，也无需为每个模型建 agent。

所有角色共用 AGENTS.md 的报告表格约定：胜率列靠前，各有明确优劣方向的指标列仅第一名加粗，
并列第一同标，其他名次正常显示；未知与描述列不排名，不使用 HTML 下划线标签。

用户要求 RSI、改进迭代或训练总控时，主 agent 先读取角色文件，再调用 `orchestrator`，
提供目标、基线、允许修改范围、轮数/时间/样本预算及停止条件。总控组织以下闭环：

```text
目标与基线 → 诊断 → 改进假设 → 实施 → 正确性检查 → 训练/验证
     ↑                                                   ↓
     └────────── 剩余预算内的下一轮 ← 比较、采纳决定与留存 ──┘
```

总控可按需委派实施和专项复核，但不要求常驻验证 agent；模型指标由既定评估程序计算。
独立 test 不用于设计改进或选模；每轮保留假设、变更、验证证据和采纳决定。
训练阶段主 agent 拉起或复用 `training_monitor`，向两个角色提供同一实例 ID、
实验配置/日志路径、已有启动授权、有序版本列表或起止范围、首阶段来源、各阶段预算和停止条件。
版本范围与预算每次指定，不写死在角色中。
总控固定使用 `gpt-6.1-sol`、`high`；监控固定使用 `gpt-6.1-terra`、`medium`。
若当前工具仅支持 task_name/message 而不能按角色名加载配置，主 agent 读取 TOML 的
`developer_instructions` 后传入任务；三个角色均以不继承完整对话的方式显式传入各自文件指定的模型与推理强度。
用 subagent 的消息/等待工具协作，复用已启动的角色，不重复创建实例。

角色文件不提供训练授权或后台 scheduler。用户只要求准备配置时，可以调用两个角色
做一次配置检查，但不得因此开始训练或持续监控尚不存在的运行实例。
运行中的监控立即首次巡检，随后约每 3 分钟检查；依赖 subagent 活跃回合，
主 agent 需关注其退出/异常，按已授权范围接续。训练进程和 agent 的存活分别核验。

主 agent 的调用示例：

> 使用 orchestrator 总控这轮 RSI，按指定目标诊断、实施并验证改进，
> 正确性检查通过后执行已授权的训练/评估；训练期间拉起 training_monitor 每 3 分钟巡检。
> 向角色传入本轮范围、预算、停止条件和状态目录；总控决定采纳和下一轮，监控通过父任务报告异常。
> 指定任务完成或预算/停止条件触发后结束，不自动追加实验。

总控按本轮指定的版本顺序，自动将每阶段 best 的完整检查点送入下一阶段。
首阶段来源单独锁定，不按版本号推断。例如指定 V7→V8，V8 继承 V7 best；
指定非连续列表时按列表顺序执行，不补造中间版本。
起点 step=0 也参加 best 选择；只看混合随机验证平均名次严格降低，未改善则沿用起点。
继承所选 best 对应的 Adam，阶段计数与 LR 按本轮约定初始化。
各阶段预算按本轮配置合计；最后一个指定阶段及其最终评估完成后停止，预算或停止条件先到则提前结束。
阶段 best、final 和全局冠军分别记录，不以版本号最大或独立 test 结果决定来源。
